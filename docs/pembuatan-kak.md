# Pembuatan PO dan KAK

Menu **Perencanaan → Pembuatan PO dan KAK** menerima satu RKA rincian sub kegiatan dalam format PDF (maksimal 2 MB). Klik **Generate dan unduh PO dan KAK** untuk membaca RKA dengan Gemini sekali dalam alur ekstraksi yang sama, mengisi dua template, menyimpan arsip, dan mengunduh satu ZIP berisi **PO (Petunjuk Operasional)** dan **KAK (Kerangka Acuan Kerja)** dalam format Word. Hasil dan arsip juga menyediakan unduh PO dan KAK secara terpisah serta PDF RKA sumber melalui sesi login aplikasi. URL halaman tetap `/dashboard/pembuatan-kak` agar tautan lama tetap berfungsi.

Template PO `src/templates/template-po.docx` berasal dari `FORMAT PO.docx` yang dilampirkan pengguna. Cover, logo WMF asli, Times New Roman, empat tabel, margin, tanda tangan, dan ukuran kertas **215 × 330 mm** mengikuti sumber. Identitas, tahun, pagu dan terbilang, deskripsi, lokasi, sumber dana, keluaran/hasil, waktu, rekening biaya, tanggal dan penandatangan diisi secara dinamis. Seluruh bagian ZIP dipertahankan byte demi byte kecuali `word/document.xml`. Jumlah baris rekening mengikuti RKA, dengan total pagu tetap berasal dari RKA. Jika rekening tidak terbaca, rincian item belanja digunakan dengan catatan pemeriksaan; angka contoh tidak disalin. `scripts/import-po-template.py "<path FORMAT PO.docx>"` memperbarui slot template tanpa mengubah dokumen sumber.

Sistem pengadaan PO mengikuti RKA hanya bila tertulis eksplisit. Form menyediakan pilihan Penyedia, Swakelola atau Kombinasi untuk menggantinya; pilihan yang sama menjadi acuan usulan strategi, metode, tahapan dan risiko KAK. Hasil kegiatan, pangkat dan fakta lain yang tidak tersedia diberi penanda untuk dilengkapi serta catatan pemeriksaan. Tanggal dan pilihan pejabat, termasuk Plt., berlaku untuk kedua dokumen. PPTK tetap untuk bagian tanda tangan KAK. Nomor urut daftar sub kegiatan tetap dicetak pada cover KAK.

Template `src/templates/template-kak.docx` mengikuti contoh KAK yang dirapikan pengguna pada 8 Oktober 2026 (`Draft-KAK-Penyediaan-Barang-Cetakan-dan-Penggandaan-2027.docx`, SHA256 `e0e0cbea2980ee47672b2cb22cd528441dab7bc29648a43596ac075b123c3b26`). Isi menggunakan Arial, judul bagian tebal, narasi rata kanan-kiri tanpa garis tabel, daftar hukum/tahapan/biaya dengan penomoran Word, dan tabel risiko serta tanda tangan rata tengah sesuai contoh. Identitas kegiatan ditampilkan tanpa awalan kode; kode tetap disimpan dalam metadata arsip. Pengisian mencakup 19 slot bernama, tiga baris risiko, tanggal, PA/KPA dan PPTK. Label tanda tangan memakai `PA / KPA` dan `Penanggung Jawab / PPTK` sesuai contoh; pilihan pejabat tetap menentukan nama/NIP. Lebar tabel, margin, bagian A–G, dan empat section isi contoh dipertahankan. Saat generate, seluruh lima section (cover dan isi) memakai **F4 210 × 330 mm** (`11906 × 18709` twips). Isi dimulai pada halaman baru dan logo cover tetap rata tengah pada lebar F4. Jumlah halaman mengikuti panjang isi; contoh cetakan menjadi satu cover dan lima halaman isi. Arsip lama tetap menyimpan DOCX aslinya; generate baru memakai format ini.

Halaman pertama memakai `cover KAK.docx` yang dilampirkan pengguna (SHA256 `281274478339cde055cb00c1893236258b440c05ea3e68db1edcfd343baad9e9`). Logo WMF asli, font Times New Roman, dan tabel identitas mengikuti cover; ukuran hasil disesuaikan ke F4. Judul cover diubah menjadi **KERANGKA ACUAN KERJA** sesuai permintaan pengguna. Program, kegiatan, sub kegiatan, nilai DPA, lokasi, serta tahun anggaran diisi dari RKA. **Nomor urut sub kegiatan pada cover** otomatis mengikuti 69 entri dalam `daftar_sub_kegiatan_rka_2027.xlsx` (sheet `Sub Kegiatan`, A6:C74) untuk DKPP TA 2027. Pencocokan memakai kode lengkap atau kode singkat RKA; kode singkat yang sama pada urusan pangan dan pertanian dibedakan berdasarkan nama sub kegiatan. Nomor hanya dipilih jika tinggal satu entri yang cocok. Jika kode kosong, nama yang sama persis setelah normalisasi huruf/spasi dapat digunakan. Contoh kode `2.09.01.2.06.0005` atau `.01.2.06.0005` menjadi nomor **26**, bukan angka terakhir kode. Jika kode dan nama menunjuk entri berbeda, tahun/perangkat daerah berbeda, atau tidak ada kecocokan pasti, nomor dikosongkan dengan catatan pemeriksaan. Input manual tetap tersedia sebagai pengganti. Nomor hasil dan checksum/lokasi baris sumber disimpan dalam JSON arsip serta ditampilkan pada hasil dan riwayat; tidak memerlukan perubahan tabel database. Arsip lama tidak diubah. Cover memiliki section/style/header terpisah; isi mulai di halaman berikutnya. Nomor cover tidak muncul pada halaman isi.

Aset daftar nomor tersimpan di `src/data/kak-sub-kegiatan-2027.json`. Untuk memperbarui daftar, periksa Excel sumber lalu jalankan `python scripts/import-kak-sequences.py "<path Excel>"` dengan runtime yang menyediakan openpyxl. Importer memvalidasi header, tahun, organisasi, nomor berurutan, dan kode unik tanpa mengubah Excel. Perubahan tahun memerlukan penyesuaian pemuatan aset dan teks form; jangan menerapkan daftar 2027 pada tahun lain. Jalankan smoke template dan periksa hasil cover sebelum deploy.

Untuk mengganti contoh tata letak, inspeksi dan render dokumen dahulu, lalu gunakan `scripts/import-kak-layout.py` dengan path DOCX contoh isi. Setelah itu jalankan `scripts/import-kak-cover.py` dengan path cover; importer cover memerlukan template isi enam tabel dan tidak dijalankan dua kali pada template gabungan. Impor cover menambahkan style dengan ID khusus, logo dan header tanpa mengubah style/penomoran/footer isi. Sumber asli tetap utuh. Saat generate, hanya `word/document.xml` dan `word/header-kak-cover.xml` diisi; seluruh bagian paket lainnya dipertahankan byte demi byte.

Gemini menghasilkan draft. Pagu memakai tahun anggaran utama, rincian memakai item belanja tanpa menggandakan subtotal, dan jumlah rincian dibandingkan dengan pagu. PPTK dipilih dari daftar pegawai aktif, dengan Muhamad Iqbal sebagai bawaan; nama dan NIP mengikuti pegawai terpilih. Penandatangan mengikuti RKA atau dipilih manual (termasuk Plt.). Lengkapi penanda kosong dan periksa narasi, dasar hukum, strategi, serta kewenangan penandatangan sebelum penetapan.

Referensi tetap adalah Renstra DKPP 2025–2029 dan Rancangan Akhir Renja DKPP 2027 yang dilampirkan pengguna. Teks sumber, tabel, nomor paragraf/halaman PDF dan checksum tersimpan di `src/data/kak-references` dan hanya dibaca di server. Pengguna tidak perlu mengunggah ulang referensi. Gemini terlebih dahulu mengekstrak fakta RKA, lalu menyusun narasi dengan bagian tujuan/sasaran dan program yang cocok. Renja 2027 hanya digunakan untuk TA 2027, Renstra untuk TA 2025–2029, dan referensi DKPP tidak diterapkan pada perangkat daerah berbeda.

RKA menjadi sumber angka KAK. Pagu/target Renja atau Renstra yang berbeda menghasilkan catatan pemeriksaan; angka indikatif tidak menggantikan RKA. Untuk contoh cetakan, Renstra memuat 2 paket/Rp120.000.000 pada 2027, sedangkan RKA/Renja memuat 1 paket/Rp29.359.021. Pemilihan dasar hukum dibatasi ID katalog yang benar-benar tercantum pada sumber. Bagian Dasar Hukum hanya mencetak daftar peraturan dari katalog secara deterministik; kalimat "Acuan perencanaan: Rancangan Akhir Renja DKPP Tahun 2027; Renstra DKPP Tahun 2025-2029" tidak ditambahkan. Renja/Renstra tetap dipakai sebagai referensi penyusunan narasi serta disimpan dalam metadata arsip. Ini tidak menyatakan semua peraturan dalam referensi masih berlaku; status, perubahan, dan relevansinya harus ditinjau sebelum penetapan. Entri Renja mengenai Keputusan Bupati 10/2023 serta kutipan Renstra yang menyebut UU 11/2020 sebagai perubahan terakhir memerlukan verifikasi dan tidak masuk pilihan otomatis. Kutipan sumber asli tetap disimpan; sistem tidak mengarang redaksi penggantinya. Identitas versi referensi, lokasi kutipan dan ID hukum terpilih ikut disimpan dalam arsip draft, sehingga arsip lama tetap dapat diunduh.

Untuk memperbarui sumber, periksa struktur dokumen, jalankan `scripts/import-kak-references.py` dengan runtime Python yang menyediakan pypdf/lxml dan kedua path lampiran, lalu tinjau hasil ekstraksi dan uji referensinya. Impor dibatasi pada struktur lampiran ini; perubahan tahun/struktur memerlukan penyesuaian importer setelah audit dokumen.

Konfigurasi menggunakan `GEMINI_API_KEY` dan `GEMINI_MODEL` yang sudah digunakan fitur AI aplikasi. Database produksi memakai migrasi `20261008051326_add_kak_documents.sql`. Metadata file PO disimpan pada `draft_json.poDocument` di tabel KAK yang sudah ada; fitur ini tidak memerlukan migrasi database atau variabel lingkungan baru. RKA, PO dan KAK memakai bucket Supabase aplikasi dan dimasukkan dalam kategori backup **Perencanaan**, termasuk backup lokal beserta metadata pemulihannya. Pada mode SQLite lokal, file berada di `data/kak-documents` (diabaikan Git). Jika penyimpanan salah satu file atau pencatatan database gagal, file yang sudah ditulis dibersihkan. ZIP dirakit saat unduh dari kedua DOCX arsip; tidak memerlukan salinan ZIP tersimpan. Arsip KAK lama tetap dapat diunduh dan diberi keterangan PO belum tersedia; unggah ulang RKA untuk menghasilkan pasangan dokumen baru.

Pemeriksaan:

- `npm run smoke:kak-template`: validasi, 19 isian, risiko, identitas, seluruh 69 nomor urut dengan kode lengkap/singkat serta nama, pengamanan tahun/organisasi/kode yang bertentangan, pengisian cover, escaping XML, pelestarian bagian ZIP, seluruh section F4, halaman baru setelah cover, dan batas 2 MB.
- Smoke template juga memeriksa identitas/angka PO, pemilihan pengadaan dan Plt., penanda data kosong, baris rekening dinamis, pelestarian ukuran kertas dan seluruh bagian ZIP PO, validasi metadata file, serta daftar file backup untuk arsip baru/lama.
- Jalankan aplikasi lokal pada port 3100 lalu `npm run smoke:kak`: autentikasi, validasi upload, unduh tidak ditemukan, menu/form.
- `npm run smoke:kak -- "<path RKA contoh pengguna>"`: juga menguji Gemini langsung, satu upload menjadi dua DOCX, isi ZIP sama persis dengan kedua file arsip, pagu contoh Rp29.359.021,00 TA 2027, delapan rincian belanja, arsip, unduh ulang RKA/PO/KAK dan kompatibilitas arsip lama. Hanya data akun/arsip sementara pengujian yang dihapus.
- Render `.tmp/kak/http-sample.docx` dan `.tmp/po-kak/http-po.docx` dengan Word/LibreOffice untuk memeriksa seluruh halaman hasil. XML yang valid saja tidak menjamin tata letak.
